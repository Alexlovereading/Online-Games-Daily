# Daily Games Hub - AI开发执行文档 PRD v1.2

## 项目目标

创建一个精品每日小游戏网站，而不是大型小游戏聚合站。

核心目标：

1. 首页打开即可直接玩热门游戏（首屏游戏区 + 下方 SEO 文案）。
2. 网站包含 7–8 个精品热门游戏（MVP 可先上 5–6 个，其余延后）。
3. 所有游戏优先使用 GitHub 已有开源项目进行二次开发；无合适开源则标为延后，不硬做。
4. 使用 Cursor / Claude Code / Windsurf 等 Vibe Coding 工具开发。
5. 本地修改 → Git 提交 → 自动部署正式环境。
6. 低服务器成本，支持 SEO 和 Google AdSense。

# 一、产品定位

Daily Games Hub

定位：

> 一个集合全球热门每日益智游戏的平台。

不是：

- 几千小游戏网站
- 游戏素材站

而是：

- 精品
- 高频使用
- 每日回访

参考体验（仅体验参考，禁止商标与品牌抄袭）：

- NYT Games 的「每日一题」产品形态
- 常见 word / sudoku / connections 类玩法

### 首页与 SEO 的关系（必须遵守）

- 首页首屏：直接可玩当日热门游戏（默认 Word 或配置中的 `featured`）。
- 首页首屏以下：简短介绍 + Related Games，不堆砌长文。
- 各游戏独立页：完整 SEO（Title / Description / H1 / 说明 / FAQ / Tips / Related）。
- 游戏区与 SEO 文案分区清晰，文案不得挡住操作。

# 二、法律与品牌约束（开工前必读）

## 2.1 商标与命名

禁止在站名、域名、页面 Title、H1、Logo、meta keywords 中使用：

- Wordle
- Connections（NYT 商标语境下的品牌名）
- 其他纽约时报 Games 官方商标

允许：

- daily word game / word guessing game
- daily word groups / word association puzzle
- 自有品牌名（如 Daily Games Hub）

## 2.2 License

接入任何 GitHub 项目前必须：

1. 确认 LICENSE（优先 MIT / Apache-2.0 / BSD；避免无 License 或仅「个人学习」声明）。
2. 在仓库 `NOTICE` 或站点 `/licenses` 页保留原作者版权与许可证全文。
3. GPL 类许可证若要求开源整个站点，默认不采用，除非产品明确接受。

## 2.3 题目与素材

- 词库、题库、国旗图等须可商用（或自制）。
- 不得直接抓取 NYT 等商业站点的每日题目。
- Flag 等素材使用明确可商用来源（如 public domain SVG）。

# 四、技术架构

## 4.1 技术栈（锁定）

Frontend：

- Next.js（App Router）
- TypeScript
- Tailwind CSS

构建与部署（必须写死，避免 AI 做成 Vercel 专用假设）：

- `output: 'export'` 静态导出
- 部署到 Cloudflare Pages
- 无 Node 服务端运行时、无 SSR 接口、无数据库
- 动态「每日」靠：构建时/运行时读静态 JSON + 客户端按 UTC 日期选当日题

代码：

- GitHub 仓库
- Cloudflare Pages 绑定主分支自动部署

数据：

- JSON 静态数据（`/data`、`/config`）
- 客户端 `localStorage` 存进度与统计

分析（选定一种即可）：

- Cloudflare Web Analytics 或 Plausible 或 GA4
- 事件名见「统一 Analytics」

广告：

- Google AdSense
- 未过审前用占位组件，禁止假点击

## 4.2 明确不做

- 用户账号系统
- 服务端排行榜（MVP）
- 自建后端 API
- 付费墙（MVP）

```text

    games/

    privacy/

    about/

    robots.ts

  components/
    GameLayout.tsx
    GameCard.tsx
    SeoBlocks.tsx                 # 说明 / FAQ / Tips / Related
    Ads.tsx                       # 含占位与正式 slot
    SiteHeader.tsx
    SiteFooter.tsx

  game-engines/
    word/
    sudoku/
    word-groups/
    game-2048/
    flag/

  config/
    games.json

  data/
    words/
    sudoku/

    flags/

  lib/
    daily.ts                      # dateKey / seed / 选当日题
```

# 六、配置与框架契约（AI 必须遵守）

## 6.1 GameConfig（`config/games.json`）

```ts
type GameConfig = {
  slug: string;              // "daily-word-game"
  title: string;
  description: string;
  path: string;              // "/daily-word-game"
  engine: string;            // "word" → game-engines/word
  daily: boolean;
  featured?: boolean;        // 首页默认游戏，全局最多一个 true
  priority: number;          // 排序，越小越靠前
  status: "live" | "soon";   // soon 不进导航可玩，可展示 Coming soon
  keywords: string[];
  related: string[];         // 其他 slug
  faq: { q: string; a: string }[];
  tips: string[];
  howToPlay: string[];
};
```

## 6.2 Daily 规则（全局统一）

```ts
// lib/daily.ts
// dateKey = 当前 UTC 的 YYYY-MM-DD
// seed = hash(dateKey + ":" + gameSlug) → number
// 所有 daily 游戏必须用同一套 dateKey，禁止各游戏各自用本地时区（除非产品以后改规则并全站替换）
```

要求：

- 页面展示「Today's puzzle · YYYY-MM-DD (UTC)」。
- 过 UTC 零点自动换题；客户端用 `dateKey` 校验缓存是否过期。
- 预生成题库时文件名与 `dateKey` 一致。

## 6.3 GameLayout 契约

```ts
type GameLayoutProps = {
  config: GameConfig;
  children: React.ReactNode;     // 游戏引擎挂载区
};
```

Layout 负责：

- 站点导航
- 标题 H1（可用 config.title）
- children 游戏区
- Ads 插槽（游戏上方或下方，不挡操作）
- SeoBlocks（howToPlay / FAQ / Tips / Related）
- Footer（含 Privacy / Licenses）

引擎负责：

- 纯游戏 UI 与逻辑
- 调用 `lib/stats` 记录完成
- 调用 `lib/analytics` 打点（start / complete / fail）
- 不自己实现整站 Header/Footer/SEO

## 6.4 Stats（localStorage）

```ts
// key: `dgh:stats:${slug}`
type GameStats = {
  lastDateKey: string;
  streak: number;
  maxStreak: number;
  played: number;
  wins: number;
  lastResult?: "win" | "lose";
};
```

## 6.5 Analytics 事件名

- `game_start` { slug, dateKey }
- `game_complete` { slug, dateKey, result }
- `nav_click` { from, to }

## 6.6 游戏接入方式（优先级）

1. **组件接入（首选）**：把开源项目改成 React 组件放进 `game-engines/*`，CSS 用模块或前缀隔离。
2. **iframe 嵌入（备选）**：仅当改造成本过高（如经典 2048 原生页）；iframe 须定高、移动端可玩，SEO 文案仍在父页面。

禁止：把整个开源仓库原样塞进 `app/` 导致多套构建体系。

## 6.7 GitHub 开源游戏优先原则（硬约束）

每个游戏的核心玩法必须优先来自经过审核的成熟 GitHub 开源项目。本站的开发重点是接入和二次修改，不是从零重写已有玩法。

允许的二次修改范围：

- 去除或替换原项目品牌、Logo、商标词和不适用文案。
- 调整视觉样式、响应式布局、无障碍与移动端操作。
- 将引擎拆成可复用组件并接入 `GameLayout`。
- 接入统一 UTC `dateKey`、确定性 seed、`localStorage` stats 和 Analytics。
- 为兼容 Next.js App Router、TypeScript、Tailwind 与 `output: 'export'` 做必要适配。
- 修复已发现的缺陷，并补充测试、SEO 区块和 AdSense 占位。

默认禁止：

- 在已有合适开源实现时，自行从零重写棋盘、判定、生成器或核心游戏循环。
- 因“接入麻烦”而绕过许可证审核，改写一个未经充分验证的简化版本。
- 复制无 LICENSE、许可证不允许商用或来源无法追溯的 GitHub 代码、题库与素材。
- 大幅改写核心逻辑后仍声称是“直接接入开源项目”。

若没有同时满足“许可证可商用、代码可审计、可静态导出、移动端可用”的候选项目：停止该游戏开发，保持 `soon` 并报告候选、阻塞原因和最小决策项，不得擅自从零开发替代品。

每个接入的游戏必须登记：

1. GitHub 仓库原始 URL。
2. 固定的 tag 或完整 commit SHA，禁止只记录会漂移的默认分支。
3. LICENSE 类型、版权人和许可证全文保存位置。
4. 实际复用的文件或模块清单。
5. 本项目的二次修改清单。
6. 依赖、构建与移动端风险。
7. 测试、`npm run build` 和真实浏览器验收结果。

# 七、多游戏扩展原则

新增游戏不能破坏架构。

流程：

1. 在 `game-engines/<name>` 放入引擎（或 submodule 后拆分）。
2. 实现与 `lib/daily`、`lib/stats` 的对接。
3. 在 `config/games.json` 增加一条 `GameConfig`（含 faq / tips）。
4. 增加路由页（或确认 `[slug]` 能静态生成该 path）。
5. `npm run build` 通过。
6. 自动获得：SEO 区块、导航、广告位、Analytics（由 Layout 提供）。

Definition of Done（每个游戏）：

- [ ] 桌面与移动端可完成一局
- [ ] Daily 与 UTC dateKey 正确
- [ ] 刷新后进度/统计符合设计（localStorage）
- [ ] 无商标违规文案
- [ ] License 已登记
- [ ] `npm run build` 成功
- [ ] 游戏页含 Title / Description / H1 / FAQ / Related

# 八、AI开发流程

## 阶段 0：选定开源并核验（每个游戏开始前）

给 AI：

```text
请针对候选 GitHub 仓库做只读分析，不要改代码。

输出：
1. 技术栈与运行方式（React/原生/构建工具）
2. LICENSE 类型与商用风险
3. 核心逻辑文件路径
4. 接入方式建议：组件改造 vs iframe
5. 需要删除/替换的品牌与文案列表
6. 预估工作量（小时）与风险
7. 仓库 URL 与建议固定的 tag / 完整 commit SHA
8. 计划复用的具体文件清单
9. 允许的二次修改范围与明确不重写的核心逻辑
10. 与静态导出、移动端和现有统一框架的兼容性结论
```

要求：

# 十四、AI开发约束

必须：

1. 游戏核心默认直接接入成熟 GitHub 开源项目，我们只做必要的二次修改；不得用自行重写替代合格的开源实现。
2. GitHub 候选必须 License 可商用、来源可追溯，并固定 tag 或完整 commit SHA。
3. 无合适开源则标 `soon`/延后并报告阻塞，不得硬写劣质山寨。
4. 保留 License、作者声明、来源 URL、复用文件与修改记录。
5. 模块化：引擎进 `game-engines`，站点壳进 `app` / `components`。
6. 每次功能性修改后运行 `npm run build`。
7. 不引入数据库与自建后端。
8. 不依赖 Node 服务器运行时（静态导出）。
9. 所有 live 游戏共享：SEO、Ads、Layout、Navigation、daily/stats 工具。
